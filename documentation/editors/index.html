Editors

pyk includes a language server, pyk lsp. An editor starts it and talks to it over the Language Server Protocol (LSP). The server is part of pyk, so there is nothing else to install: an editor only needs to know how to start it.

The server gives:

  • Diagnostics: the first error in a file, from lexing, parsing, the module system, names, types or mutability. An error in an imported module is shown at the import that reaches it.
  • Hover: the type of the expression, binding, parameter or definition under the cursor, and for a name, the ## comment above its definition.
  • Go to definition: where a name is bound, in the same file, in a module it imports, or in the standard library.
  • Outline (document symbols): the defs, the top-level bindings and the imports.
  • Completion: keywords, builtins, the names in scope, and after m. the names that module m exports.

Each document is checked as a program, together with the modules it imports. A module that is open in the editor is read from the editor, so an unsaved change is seen by every file that imports it.

Options and settings

  • --stdio uses standard input and output. It is the only transport and the default; it is accepted because some editors always pass it.
  • -L DIR / --lib-path DIR, and the environment variable PYKING_LIB_PATH, add library directories, as for pyk.
  • --log FILE appends every message in and out, and any internal error, to FILE. Use it when an editor’s setup does not work: standard output carries only the protocol, and editors often hide standard error.

An editor can send two settings, as initializationOptions or as the pyking section of its workspace configuration:

settingdefaultmeaning
libPath[]more library directories, searched after -L
diagnostics"change""change": check as you type, once typing pauses; "save": check only when a file is opened or saved

The examples below assume pyk is on your PATH. If it is not, write its full path in place of pyk.

Emacs

pyking-mode.el, Pyking’s Emacs mode, registers pyk lsp with eglot, which is built into Emacs 29 and later. It ships with Pyking, in tools/emacs/ of the installation: under Homebrew that is $(brew --prefix)/opt/pyking/libexec/tools/emacs/; with install.sh ~/.local/share/pyking/tools/emacs/ (/usr/local/lib/pyking/tools/emacs/ with --system); with the .deb /usr/lib/pyking/tools/emacs/; and with Nix ~/.nix-profile/libexec/pyking/tools/emacs/. When it does not work

  • Run pyk --version in a terminal. If it fails, pyk is not on the PATH the editor sees; give the editor the full path instead.
  • Add --log FILE to the command, for example pyk lsp --log /tmp/pyk-lsp.log, open a .pyk file, and read the log. If the file is empty, the editor did not start the server.
