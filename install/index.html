Install

Pyking is one program, pyk, together with its standard library. Compiling, interpreting and the REPL need nothing else.

macOS

Install with Homebrew:

brew upgrade pyking updates it and brew uninstall pyking removes it.

Linux and WSL

This installs the latest release for your user, with no sudo: pyk goes in ~/.local/bin/. Add that directory to your PATH if the installer says it is not there. Run the command again to update. Options go after sh -s --:

Nix

On Linux and macOS, with flakes enabled, Nix builds Pyking from source. Name the release you want in place of <version>:

nix profile remove pyking removes it. tools/packaging/nix/default.nix is also a function for nixpkgs’ callPackage.

Docker

The image runs pyk repl unless the command line names another command, in the current directory, which is the container’s /work:

To use the playground, the notebook or the help, publish the port and open the link it prints:

A shell in the image is docker run --rm -it -v "$PWD:/work" ghcr.io/pyking-lang/pyking bash.

ghcr.io/pyking-lang/pyking:full also holds Python, node, a C compiler, a JDK and OCaml, so pyk compile --run works for every target.

What else you may need

  • pyk notebook and pyk playground need nothing more: pyk serves them itself.
  • Running compiled output needs that target’s own tools: node for JavaScript, a C compiler for C, a JDK for Java, ocamlopt for OCaml and python3 for Python. Compiling alone needs none of them.
  • Interpreting a program that has an external module of its own needs the OCaml compiler pyk was built with. The standard library works without it.
