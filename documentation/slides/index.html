Code on slides

pyk highlight writes Pyking code coloured the way the playground colours it, as text a slide program such as Keynote pastes and keeps as text: the colours stay, and a reader of the slides exported to PDF can still select the code and copy it.

Open the HTML in a browser, or the RTF in TextEdit, select the code, copy it and paste it on the slide.

From the playground

In the playground, Copy for slides does the same for the code in the editor — the selection, or the whole program when nothing is selected — and puts it on the clipboard ready to paste on a slide. It is in the editor’s right-click menu and on Alt+Shift+C (Option+Shift+C on a Mac). Its options — the colours, font, size, background and spaces — are under Settings, Copy for slides, with a preview, and so are a switch that puts a Copy for slides button above the editor and, under Keys, its key.

Indentation that survives a PDF

Exporting to PDF and copying the code back out tends to lose the spaces at the start of each line, and with them Pyking’s blocks. So pyk highlight writes indentation with non-breaking spaces, which a PDF keeps. Pyking reads a non-breaking space as a space, so code copied out of the PDF runs as it is.

--spaces all writes every space as a non-breaking one, except those inside a string, which are part of what the program prints, and --spaces none writes ordinary spaces only. Keynote’s “Paste and Match Style” pastes the plain text, which keeps the non-breaking spaces too.
