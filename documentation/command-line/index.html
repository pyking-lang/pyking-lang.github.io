Command line

Everything Pyking does is one program, pyk. Given a file, it runs it with the interpreter. Given a command word first, it does that instead: compile, start the REPL, serve a notebook or the playground, and so on.

pyk on its own prints a short usage and exits with status 1. pyk --help prints all of it: every flag, the targets and their versions, the warnings, and a paragraph on each command. pyk --version prints the version.

The commands

CommandWhat it does
pyk prog.pyk [-- args]Run the program with the interpreter.
pyk prog.pyk -t T [-- args]Compile it for target T and run it.
pyk compile prog.pykCompile it (default target: python). pyk c is the same.
pyk replStart the REPL.
pyk notebook book.mdServe a notebook and open it in the browser.
pyk playgroundServe the playground locally.
pyk pykhelpServe this documentation locally.
pyk serve [dir or file]Serve a directory’s files, such as a compiled web page.
pyk example [name]List the bundled examples, or save one.
pyk highlight fileColour Pyking code for slides: HTML, RTF or text.
pyk lspThe language server, started by an editor.
pyk dapThe debug adapter, started by an editor.
pyk plugins dirBuild the interpreter’s plugins for a directory of libraries.

Pyking is statically typed: every program is type-checked before it runs or compiles, and there is no flag to skip that.

Running a program

runs the program with the interpreter. Nothing is written to disk. The interpreter is the reference for what a program means: it reports a runtime error as a Pyking error, with its position in the source and the calls in progress.

Everything after -- is given to the program, and sys.args() answers with it:

import sys

for name in sys.args():
    print("hello,", name)

With -t, the program runs on a compiled target instead of the interpreter. It is compiled into build/, built and run from there, and nothing is put beside build/:

--tinyweb-log prints what a program sends its tinyweb page, and what the page answers, on standard error while it runs. It applies to pyk prog.pyk and pyk repl.

pyk compile

pyk compile translates the program for a target, builds it with that target’s own tools, and leaves an executable beside the source. The target is python unless -t says otherwise:

Compiler targets lists every target, what it writes and what it needs to run.

FlagWhat it does
-t T, --target TCompile for target T: a family (python, node, web, iweb, c, c-gc, java, ocaml, pyking) or a version (python14, c89, java8, …).
-o FILE, --output FILEName the executable. build/ goes beside it: -o out/hi writes out/hi and out/build/.
--runBuild and run what was compiled, printing each command first.
--stdoutPrint the generated code for the program’s own module, and write nothing.
--no-buildWrite build/ and its Makefile, and build nothing.
--releaseRemove every call to debug(). print() is kept.
-- argsWith --run: arguments for the program.

What it writes

Everything generated goes into a directory build/ beside the executable: the program’s file, one per module it imports, the target’s runtime files, and a Makefile. Then pyk compile builds it and puts the executable in place:

  • for C and OCaml, the binary itself;
  • for Python, node and Java, a short shell script that runs what is in build/;
  • for web and iweb, nothing: the page and its files are all in build/.

build/ is made afresh on every compile. A build/ that an earlier pyk compile made is replaced. Any other build/ is left alone and the compile is refused, so pyk never removes a directory of yours; move it or compile elsewhere with -o.

build/Makefile holds the same commands --run uses: make builds, make run runs (make run ARGS='a b' passes arguments), and make clean removes what make made. Each tool is a variable, such as CC, JAVAC or PYTHON.

The Java targets name the file and its class in Java’s style: foo_bar.pyk becomes build/FooBar.java. The pyking target writes its one .pyk file where -o says, and builds nothing.

--run

--run builds what was compiled and runs it with the target’s own commands. Each command is printed on standard error, after $ , so the program’s own output on standard output stays clean:

A web or iweb page is run by serving it: --run starts pyk serve and prints a link to the page.

$PYTHON, $NODE, $CC, $JAVAC, $JAVA and $OCAMLOPT choose the tool to use where there is a choice.

--run cannot be combined with --stdout, since there is no file to run. pyk compile without --run runs nothing, so it refuses arguments after --.

--stdout

prints the generated code and writes nothing. It shows the program’s own module only; the modules it imports are files of their own. This is a quick way to see what Pyking compiles to; the playground’s Compiled code tab shows the same.

--release

--release removes every call to debug() before the program is compiled, so a release build writes nothing to standard error through debug. It applies to pyk compile only: the interpreter always runs a program as written.

pyk repl

Starts the REPL. --use mutation turns a feature on from the start, as a use line typed at the prompt would; the features are mutation, pointers and objects. pyk repl takes no file. See REPL.

pyk notebook

Serves a Markdown notebook, whose Pyking code blocks can be edited and run in the browser, and prints a link to open it. The page reloads when the file changes.

FlagWhat it does
--port NServe on port N.
--mode studentThe default: a task’s solution and tests stay hidden until the reader asks for them.
--mode teacherShow every block, and what test mode finds under each.
--mode testServe nothing: run every cell, task and solution, check each against the expected output after it, print file:line: message for each problem, and exit with 1 if there is one.
--to-jsonWrite the notebook’s Markdown as JSON: book.md to book.json.
--to-markdownWrite a notebook’s JSON back as Markdown.
--json-schemaWith no file: write the JSON Schema of every notebook’s JSON, notebook.schema.json.
-o FILEWith the three above, name the file written; -o - prints it.
-W...The warnings the page shows under a block.

The three conversions never write over an existing file of the default name. See Notebook.

pyk playground and pyk pykhelp

pyk playground serves the playground and prints a link to it. pyk pykhelp serves this documentation, with its runnable examples, the same pages the playground’s Help tab shows. Both run until Ctrl+C.

pyk serve

Serves a directory’s files as they are: the current directory by default. Given a file, it serves the file’s directory and prints a link to the file. This is how to open a page compiled for web or iweb, since a browser will not load its modules from a file:// address:

Ports and addresses

pyk notebook, pyk playground, pyk pykhelp and pyk serve start at port 8000 and take the first free port up to 8019, or any free port if those are all taken. --port N asks for port N. They listen on 127.0.0.1, or on the address $PYKING_WEB_HOST names, for example 0.0.0.0 for every interface, as in a container.

pyk example

pyk example lists the bundled example programs with a line on each. pyk example NAME saves the one named in the current directory, and refuses if a file of that name is already there. The playground’s Examples menu offers the same programs.

pyk highlight

Writes Pyking code coloured as the playground colours it, for pasting into slides: HTML with every style inline, RTF, or plain text. FILE is a program or a notebook. pyk highlight --help lists its options; Code on slides explains them.

pyk lsp and pyk dap

An editor starts these; you do not run them yourself. pyk lsp is the language server and pyk dap the debug adapter. Both talk over standard input and output; --stdio is accepted and is the only transport. --log FILE appends every message to FILE, which helps when finding out what an editor sent. See Editors and Debugging.

pyk plugins

For library authors. The interpreter runs a module implemented in another language through its OCaml implementation, NAME_external.ml, loaded as a plugin. Without a prebuilt plugin, pyk compiles one on first use into ~/.cache/pyking, which needs the same ocamlopt that pyk was built with. pyk plugins DIR builds the plugin of every library in a directory of libraries ahead of time, beside its implementation, and skips any that are up to date. The standard library’s plugins ship with pyk. See Compiler targets.

Warnings

A warning is printed on standard error and the program still runs or compiles. The -W flags apply to pyk prog.pyk, pyk compile, pyk repl, pyk lsp, pyk dap and pyk notebook, in the order given.

FlagWhat it does
-WnameTurn warning name on.
-Wno-nameTurn it off.
-WallTurn every warning on.
-wTurn every warning off.
-WerrorMake every warning that is on an error, which stops the program before it runs.
-Werror=nameMake one warning an error, and turn it on.
-Wno-error, -Wno-error=nameUndo those.
WarningOn by defaultReports
unused-bindingyesA name bound with = that nothing in its scope uses.
unused-functionyesA def that is never called or passed on, or only calls itself.
unused-varyesA var that is never read. Writing it with := does not count.
shadowed-updateyesAn = inside a block, never used, that shadows a name from outside: an update written as a new binding.
shared-fillyesarray(n, v) where v is itself an array, so every element is the same one.
unused-pattern-varnoA name a case pattern binds that its arm never uses.
unused-parameternoA parameter its function or lambda never uses.
unused-loop-varnoA loop’s accumulator, a for variable, or a name a comprehension binds, that the loop never uses.

A name starting with _, a public name, and a name in a library’s module are never reported.

The library search path

import name looks for the module in these places, in order, and the first that has it wins:

  1. the directory of the file that imports it: name.pyk, or name_external.pyk for a module implemented in another language;
  2. each -L directory, in the order given;
  3. each directory in $PYKING_LIB_PATH, separated by : (by ; on Windows);
  4. the lib/ directory beside the pyk executable, which holds the standard library.

A -L directory holds one folder per library: -L libs finds libs/shapes/shapes.pyk for import shapes. The flag can be written -L DIR, -LDIR, --lib-path DIR or --lib-path=DIR, and repeated. When a module is found nowhere, the error lists every path it looked in. See Modules.

Errors and exit codes

Every error names the file, the span in it, and the kind of error, and is wrapped to 70 columns:

The kinds are Lexing error, Parsing error, Module error, Name error, Type error and Runtime error. A construct a target cannot compile is refused before any code is written, naming the target:

A command-line mistake prints Usage error: and the short usage.

StatusWhen
0The program ran to its end, or the command did what it was asked.
1An error in the program (lexing, parsing, a module, a name, a type, a runtime error), a warning made an error by -Werror, a usage error, or a failed --mode test.
codeThe program called sys.exit(code).
the program’s ownWith --run or -t: the status of the compiled program, or of the build step that failed. 127 if a tool was not found.
2A fault in pyk itself. The message says so; please report it.

Looking inside the compiler

These flags are for people curious about, or working on, the compiler.

FlagWhat it does
--tokensPrint the token stream first.
-t pykingCompile Pyking to Pyking: the program as the front end understood it, with inferred types and the loops the tail-call pass built.
--symbolsWith -t pyking, also print each node’s symbol.
--no-tail-call-optLeave tail calls as calls, instead of turning them into loops.
--no-typecheckingOnly with pyk compile -t pyking: print the program as parsed, with nothing inferred.
--type-experimentCheck the program with an experimental, partial type checker.
