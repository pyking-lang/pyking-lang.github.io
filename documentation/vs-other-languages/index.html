Pyking vs. other languages

Pyking has Python’s syntax and ML’s semantics. Programs are indented, use def, if, for, while and match, and look like Python. But a name bound with = never changes, every block is a scope, types are static and inferred, and data is built from datatypes and taken apart with an exhaustive match. A use line at the top of a module adds more: use mutation adds variables, arrays and mutable structs, use pointers adds C-style pointers, and use objects adds Java-style classes and interfaces.

This page is for readers who know one of the languages Pyking compiles to. Each part says what carries over, what does not, and what the compiler writes for that language. The full list of targets is on Compiler targets, and the language itself is in the language reference.

String interpolation, everywhere

Every Pyking string may hold $name or ${expression}. The parser rewrites it before anything is checked: "n = $n, next ${n + 1}" is "n = " + string(n) + ", next " + string(n + 1), so each target compiles a plain concatenation, and a value is shown as print shows it on every target. For Python:

Seeing the generated code yourself

Every example on this page can be compiled for any target.

  • In the playground, open the Compiled code tab, pick a target from the list and press Compile. The generated code appears above, and Run builds and runs it.
  • On the command line, pyk compile -t <target> --stdout prog.pyk prints the generated code instead of writing it to build/, and --run builds and runs it with the target’s own tools. See Command line.

The generated-code excerpts below come from the compiler, and the site’s tests check that it still writes them.

Semantics

The same as Python: values and evaluation order (left to right), lists, strings, closures and first-class functions, recursion, and, under use objects, classes whose objects are shared by reference.

Different:

  • Types are static and inferred. "n = " + 5 and 1 + 2.0 are errors before the program runs, not at the line that reaches them. if xs: is an error too: a condition must be a Bool.

  • Every block is a scope. A name bound inside an if is gone after it:

    n = 3
if n > 0:
    sign = "positive"
print(sign)

    Bind the if itself instead:

    n = 3
sign = if n > 0 then "positive" else "not positive"
print(sign)

  • = never changes a variable. It makes a new binding, and a function written before it keeps the old one:

    x = 1
def show(): x
x = 2
print(x, show())

    This prints 2 1. Python would print 2 2.

  • Int division truncates, and Int and Float never mix. -7 / 2 is -3 and -7 % 2 is -1, as in C. Python gives -4 and 1. float(n) and int(x) convert:

    print(-7 / 2, -7 % 2, 7.0 / 2.0, float(7) / 2.0)

  • No exceptions and no None for every type. A function that may have no answer returns an Option:

    def find(xs: [Int], target: Int) -> Option(Int):
    loop i = 0 for x in xs:
        if x == target:
            return Some(i)
        i + 1
    None

print(find([4, 5, 6], 5), find([4, 5, 6], 9))

  • match must cover every value. A match that misses a case is refused, naming the value it misses. Python’s match does nothing.

  • A negative index is an error. xs[-1] stops the program in the interpreter. On the Python target it is Python’s own behaviour, so it counts from the end there.

  • Nothing is exported without public, and a public function annotates all its parameters and its result.

  • Map never changes; a change returns a new map. MutMap, under use mutation, is the one that is written in place, like a dict.

The same small program is compiled in every part of this page. It has one datatype, one match and one var, which a function writes:

use mutation

datatype Shape:
    Circle(r: Int)
    Rect(w: Int, h: Int)

def area(s: Shape) -> Int:
    match s:
        case Circle(r): 3 * r * r
        case Rect(w, h): w * h

var total = 0

    total := total + area(s)

for s in [Circle(1), Rect(2, 3)]:
    add(s)

Targets and limits

  • What it takes: everything. Python is the reference target.

  • Running it: python3 prog.py. The output imports little: dataclasses where it declares a datatype, and the compiled modules of the Pyking libraries it uses.

  • 3.12 or 3.14: type aliases and class type parameters need 3.12. The two versions differ in one place: 3.12 quotes a field whose type is not declared yet, such as a datatype holding itself, and 3.14 writes it bare.

    datatype Tree(a):
    Leaf
    Node(left: Tree(a), value: a, right: Tree(a))

def size(t):
    match t:
        case Leaf: 0
        case Node(l, _, r): size(l) + 1 + size(r)

print(size(Node(Leaf, 7, Node(Leaf, 8, Leaf))))

  • Where the output differs: Python’s integers never overflow, so 2147483647 + 1 is 2147483648. Python’s recursion limit is 1,000 calls by default, so a deep recursion that is not a tail call can fail compiled and run in the interpreter. A negative index counts from the end.

Semantics

The same as JavaScript: closures and first-class functions, objects shared by reference (under use objects, and mutable structs), and a single thread. A tinyweb program’s callbacks run one at a time, as on the event loop.

Different:

  • Types are static. A misspelled field or a wrong argument is found before the program runs.

  • Int and Float are separate types, and / on two Ints truncates. Char is a type of its own, not a string of length one.

  • Nothing converts implicitly. "n = " + 5 is an error; write "n = " + string(5):

    print("n = " + 5)

  • == compares structure. Two lists, tuples or datatype values are equal when their parts are. There is no ===, and no reference equality except same(a, b) for mutable values.

    print(7 / 2, -7 / 2, 7.0 / 2.0)
print([1, 2] + [3], [1, 2] == [1, 2], (1, "a") == (1, "a"))
print("n = " + string(5))

  • No undefined and no null. A missing value is an Option. An unbound name is a compile-time error.

  • Every block is a scope, and nothing is hoisted. A binding is visible from where it is written to the end of its block. Functions in a block can call each other in any order.

Targets and limits

  • What it takes: everything the type checker accepts, on all six targets.
  • node: foo.js, the shared pyk-runtime.js and a package.json that marks the files as ES modules. Run with node foo.js.
  • web: foo.html and the same .js files. print writes to the browser console. A page must be served over HTTP: pyk compile -t web --run starts pyk serve and prints the page’s address. tinyweb programs draw on the page.

Semantics

The same as C: Int arithmetic that truncates on division, mutable structs passed as references, arrays that know their length, and pointers to variables, with & and * written as in C.

Different:

  • Memory is managed. The program never frees anything, and nothing it holds is freed under it.

  • No undefined behaviour from memory. In Pyking an index outside an array or a list is a runtime error with a message (plain C output does not check it; c23-gc does). There is no null pointer, and a pointer has no arithmetic.

  • Strings are values. + joins two Strings into a new one, s[i] is a Char (a Unicode code point), and len(s) counts code points.

  • Functions are values, and closures exist. A function can return a function that remembers its arguments, and a function without type annotations works on any type that fits:

    def adder(n: Int) -> (Int) -> Int:
    lam x. x + n

def first(pair):
    (a, _) = pair
    a

add3 = adder(3)
greeting = "Hello, " + "world"
print(add3(4), first((1, "x")), first(("y", 2)))
print(greeting, greeting[0], len(greeting))

  • Modules, not headers. A file is a module; it exports what it marks public, and import reads it. There is no preprocessor.

Targets and limits

  • Plain C (c89, c99, c23) allocates with malloc and never frees, and checks no index. It refuses what needs a heap that is freed: lists, a datatype holding itself, and a closure that outlives the function that made it. Each refusal names c23-gc. The three versions write the same program; they differ in comments, where declarations go and how Bools are spelled.
  • c23-gc takes everything else, and checks every index. It needs bdwgc: apt install libgc-dev on Debian and Ubuntu, dnf install gc-devel on Fedora, brew install bdw-gc on macOS. pyk compile -t c-gc --run finds it.
  • No C target compiles a polymorphic parameter (all a. (a) -> a): one C function cannot serve every type.
  • Running it: cc -std=c99 foo.c -lm && ./a.out for plain C; cc -std=c23 -DPYKING_GC foo.c -lgc -lm for c23-gc.
  • Where the output differs: int is 32 bits on every common C compiler, and overflow is undefined behaviour; in practice 2147483647 + 1 is -2147483648. Division by zero is undefined too. A file using Float turns off floating-point contraction, so a * b + c rounds as on the other targets.

Semantics

The same as Java, under use objects: objects shared by reference, one parent class and any number of interfaces, dynamic dispatch, abstract classes, override, and garbage collection. Type variables work as generics do.

use objects

class Animal(name: String):
    def speak(self) -> String:
        self.name + " makes a sound"

class Dog(dog_name: String) extends Animal(dog_name):
    override def speak(self) -> String:
        self.name + " barks"

pets: [Animal] = [Animal("Cat"), Dog("Rex")]
for p in pets:
    print(p.speak())

Different:

  • Functions and data live outside classes. A program is a file of statements and defs; classes are only needed for objects.

  • Immutable by default. = is like final; a variable needs var and use mutation.

  • Datatypes and an exhaustive match, like a sealed interface of records with a pattern switch, but the compiler always checks that every case is covered.

  • No null and no exceptions. A missing value is an Option, an error a Result, and panic stops the program.

  • == compares structure, also on strings, lists and datatypes. On a class it calls the class’s eq method, and is refused if there is none. same(a, b) asks whether two names hold one object.

    struct Point(x: Int, y: Int)

print(a == "abc", Point(1, 2) == Point(1, 2), [1, 2] == [1, 2])

Semantics

Almost all of the core is the same as OCaml: type inference, immutable bindings, variants and an exhaustive match, Option and Result, closures, guaranteed tail calls, and var/:= as a ref cell.

Different:

  • Statements, not expressions everywhere. A block is a sequence of statements, and its value is its last one. if and match give a value where one is bound or returned.

  • return, break and continue. A function can stop early, and so can a loop:

    def find(xs: [Int], target: Int) -> Option(Int):
    loop i = 0 for x in xs:
        if x == target:
            return Some(i)
        i + 1
    None

print(find([4, 5, 6], 5), find([4, 5, 6], 9))

  • Overloading and implicits. Two defs may share a name, told apart by their argument types. OCaml has neither.

    def int::twice(x: Int) -> Int: x * 2
def string::twice(x: String) -> String: x + x

print(twice(21), twice("ab"))

  • One + for Ints, Floats, Strings and lists, and one == and print for every type that has them. OCaml has +., ^, @ and no generic printer.

  • Classes are Java-style, with nominal types, single inheritance and explicit override. They are not OCaml’s structural objects.

  • No functors. Modules are files, with public names.

The OCaml target runs Pyking’s type checker and reads the types back, so the output has no type annotations: OCaml infers them again.

The same program as in the other parts:

use mutation

datatype Shape:
    Circle(r: Int)
    Rect(w: Int, h: Int)

def area(s: Shape) -> Int:
    match s:
        case Circle(r): 3 * r * r
        case Rect(w, h): w * h

var total = 0

def add(s: Shape):
    total := total + area(s)

for s in [Circle(1), Rect(2, 3)]:
    add(s)
print(total, total / 4)

Targets and limits

  • What it takes: everything the type checker accepts, except a few shapes OCaml cannot be given. The main ones: a break or continue that is neither the last thing in the loop body nor guarding the rest of it; printing a value whose type is a type variable; and a generic class whose method returns the class at other type arguments. Each is refused at compile time with a source position.
  • Running it: ocamlopt foo.ml -o foo && ./foo. The output needs only the standard library, and builds with every warning on.
  • 4.14 or 5.5: the output is written for both. 4.14 lacks a few newer library functions, such as List.take, so the compiler does not use them there.
  • Where the output differs: OCaml’s int is 63 bits, so 2147483647 + 1 is 2147483648, where Java and C give -2147483648. Division by zero raises Division_by_zero.
